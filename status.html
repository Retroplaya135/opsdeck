Capability matrix — what is actually real

The distinction that matters: computed from data, versus displayed as decoration.

CapabilityStatusHow it is implemented
Forecastingreal Holt-Winters additive triple exponential smoothing. α/β/γ grid-searched against a withheld holdout, not in-sample fit. Prediction bands are ±1.96σ of residuals widened by √h.
Trend detectionreal Mann-Kendall nonparametric test with tie and continuity correction, plus Theil-Sen for slope magnitude. Reports p-values, not vibes.
Anomaly detectionreal MAD robust z-scores. Deliberately not mean/σ, which a genuine spike inflates until it hides itself.
Changepointreal CUSUM with 200-sample bootstrap confidence. Reports the date a level shifted, not just that it did.
Seasonalityreal Autocorrelation period detection + classical additive decomposition, so a weak Friday can be separated from a falling trend.
Capacity planningreal Erlang-B recurrence → Erlang-C. Occupancy, ASA, service level, minimum staffing. Cross-checked against the textbook A=5,N=8 case.
Experiment analysisreal Two-proportion z-test with unpooled 95% CI, plus a power check that flags underpowered arms.
Segmentationreal k-means++ over standardised behaviour vectors (rate, show, close, AHT) — not over volume, which would just restate the leaderboard.
Churn scoringreal Logistic regression with L2, gradient descent, AUC via the Mann-Whitney identity.
Excel / Sheets inreal RFC-4180 CSV parser (quoted commas, escaped quotes, BOM). Referential integrity enforced on import — bad clientId rows are rejected, not silently dropped.
Sheets read-syncpartial GET against a published-to-web CSV URL. Works with zero setup; fails visibly on a bad URL.
Sheets write-backnot built Requires Google OAuth and a Cloud client ID only the account owner can create. Scaffolded and documented in Settings, left honestly disabled rather than faked.
Sentimentrule-based Deterministic function of the numeric CSAT score, so the tag can never contradict the number beside it. No text classifier, no language model.
Authenticationreal HttpOnly + SameSite=Strict session cookie, HMAC-signed with a per-process key. Constant-time token comparison, per-IP login rate limiting, strict CSP, realpath traversal containment. Per-user accounts with roles and SQL client scope. TLS optional via env vars.
Messy-CSV ingestreal Currency symbols, thousands separators, accounting negatives, percentages, Excel serial dates, aliased and case-variant enums, duplicate keys, orphaned foreign keys. Ambiguous values rejected, never guessed; every coercion reported for audit.

On “AI”: everything above is applied statistics and classical machine learning running locally in the page. That is a deliberate choice, not a shortfall — an operations console needs results an operator can audit and reproduce, and every figure here carries the test statistic that produced it. Blockers before this touches a real client

Ordered by what would hurt first. Nothing here is hypothetical.

P0

Data is still modelled, not a client’s

The import path is now proven against a fixture full of real CSV pathologies, which is the hard half — but the resident dataset is still the seeded case study. Pointing it at a live export is a small change to one module and a large change to confidence. Until that happens no figure here describes a real business.

P1

TLS is optional, not on by default

Accounts, roles and SQL client scoping are in place. The server still binds to 127.0.0.1 unless you move it. Set OPSDECK_TLS_CERT and OPSDECK_TLS_KEY (or put a terminator in front) and the cookie gains Secure before binding wider.

P1

Audit log is not tamper-evident

Sign-ins, views, imports and denials append to var/audit.jsonl. There is no hash chain, so a hostile admin can rewrite history. That is the next step if the log must survive the operator.

P1

Smoke tests check structure, not correctness

The 18 view tests assert each route renders and contains no NaN/undefined. They do not assert that any displayed number is right — a view could show a confidently wrong figure and pass. Closing that needs fixture data with known expected outputs per view.

P2

app.js is 2,940 lines with shared mutable state

Deliberate trade-off for the zero-build constraint, and the engine is cleanly separated. But two people cannot easily work in it at once, and nothing structurally prevents one view from reaching into another's cache.

P2

ES modules need a server

Opening index.html from the filesystem no longer works — modules require HTTP. That was the price of making the engine importable and testable, and it is worth it, but it is a real change to how this is run.

Defects found and fixed in this build

Listed because a status page that only reports success is marketing. Each of these was live in the code and would have shipped.

bug

Changepoint returned the last index, always. at was derived from whichever of hi/lo updated most recently, but CUSUM returns to ~0 by construction, so floating-point dust on the final step beat hi=0 and pinned every changepoint to the end of the series. Caught by the planted-shift test. Now uses argmax|S|.

bug

Seasonal index was rotated against its own labels. decompose() indexes phase by position in the series, which equals day-of-week only if the window starts on a Sunday. The panel printed Friday’s index (−18.9) next to Friday’s number, which was the single highest mean in the table. Now maps weekday→phase explicitly.

bug

Stochastic rounding destroyed the entire appointment stream. Math.round(3.4 × 1.7%) is 0 for every daypart, so appointments silently went to zero while dial counts still looked healthy. Fractional expectation is now carried as a Bernoulli draw, preserving E[x].

calibration

Appointment rate was a warm-transfer number. 11% per connect produced 5.9 booked/agent/day against a 0.6 target — every seat graded as a superstar and the keeper/fire logic became decorative. Recalibrated to 1.7% cold-outbound; roster now averages 0.69/day.

calibration

Weekend seasonality was inverted. Weekday weighting was applied to the dial day, then the appointment was pushed 1–9 days out, smearing it onto Sundays. Appointments now deflect off Sunday and spill both directions — an earlier one-way fix piled every deflected booking onto Monday.

calibration

Zero detractors across 390 reviews. CSAT variance was too narrow, giving a 4.49 average and +95 NPS — a distribution no contact centre has ever had, and one that left the flagged-review workflow with nothing to show. Now 15% detractors, NPS +39, 107 flagged.

calibration

Every open ticket rendered as SLA-breached. Open requests drew their open date from the same 60-day window as resolved ones, so a 4-hour-SLA urgent ticket could sit open for seven weeks. Open tickets are now recent by construction; attainment reads 85.7%.

bug

Charts zero-filled their undefined edges. A centred moving average is undefined for the first and last half-period; mapping those nulls to 0 drew the trend line diving to the axis at both ends. Same class of bug in the forecast band. Both now trim or track the actuals instead.

test

Two test expectations were wrong, not the code. The sample-size test guessed 30–200 per arm; the correct answer for 0.20→0.30 at 80% power is 294, verified independently. The zToP(0) assertion demanded tighter precision than the Abramowitz-Stegun erf approximation’s own documented 1.5e-7 bound.

bug

Imports were silently destroying money. parseFloat("8,400") returns 8, and parseFloat("$8,400") returns NaN, which the old path coerced to 0. An $8,400 retainer imported as $8 or $0 with no warning anywhere, and every margin figure downstream was quietly wrong. Replaced with a dedicated ingest layer that handles currency, separators, accounting negatives, percentages and Excel serial dates — and rejects ambiguous input instead of guessing.

bug

Unparseable optional fields fell back to zero. Caught by the messy-CSV suite: 8400USD in an mrr column was importing the row with mrr=0. A value that exists but cannot be read is not a missing value — the row now rejects. Blank still takes the fallback, because a genuinely absent MRR and an unreadable one are different facts.

bug

Strict CSP broke two of my own pages. Enabling script-src 'self' immediately blocked the inline module scripts in the test and smoke runners — the policy working exactly as intended. Extracted to real files rather than punching an 'unsafe-inline' hole through the policy to make my own pages load.

bug

The error boundary itself did not work. Its fallback wrote the failure card via innerHTML — so when the thing throwing was the innerHTML write, the catch block threw again, the boundary was defeated and no trace survived. Found by firing a real throw through it instead of assuming it worked. Now logs before rendering and falls back to textContent, verified against both a pathological and an ordinary failure.

test

Smoke runner hung for 26s on a single route. It waited on requestAnimationFrame, which browsers throttle hard in a background iframe. The renders are synchronous, so a single macrotask is sufficient.

perf

Insights view ran the full engine on every navigation. Mann-Kendall (O(n²)), a 200-sample CUSUM bootstrap and k-means, recomputed per visit, put it at 27.7ms — past a frame budget for a result that cannot change until the data does. Memoised, with invalidation on data and threshold changes.

Data provenance

MODEL DATA. Every figure in this application is generated by a seeded simulation in js/casestudy.js. It is not a client's real numbers and must not be quoted as one.

The generator is parameterised by a visible assumption register — eleven named parameters, each with its reasoning, rendered in the app itself on the Reporting view. Those are declared assumptions, not citations: no external study is referenced, because inventing a citation would be worse than declaring an assumption. The seed is fixed, so every number reproduces exactly on any machine.

Derived rates land inside their declared bands, which is the check that the model is internally consistent rather than just plausible-looking: connect rate 28.2%, appointments per connect 2.02%, booked per agent-day 0.69 against a 0.60 target, show rate 72.6%, close rate on sat 36.5%.

Verify any claim here yourself: tests.html runs the engine suite and smoke.html drives every route in your browser, and Reporting renders the full assumption register. This page is hand-maintained — there is no CI checking it against the code, so treat it as a snapshot of this build, dated by the numbers in it rather than by a timestamp.
